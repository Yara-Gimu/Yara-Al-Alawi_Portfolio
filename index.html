Stage 01 · Code ArchitectureMirrors of Time05 / 14
Built on Robert Nystrom's "Game Programming Patterns"

One Pattern per Problem

Each system in the game is matched to a pattern, so new regions, languages and platforms can be added without rewriting core code.

COMMAND

Input & Local Rewind

Buttons create commands (Jump, Move), not direct calls. Stored commands run in reverse to restore broken bridges and pottery.

STATE

Nawar's Movement

Idle · Run · Jump · Crawl as separate states. Coyote time lives in a short Falling state with its own timer.

STATE

Wahej & Game Flow

WahejWeak → WahejHappy as the story moves on. MainMenu → Loading → Gameplay with no black loading screen.

OBSERVER

Quests, Tutorial & UI

A stone sends one "StoneCollected" event; the UI, frame glow, audio and Wahej all react to it. No spaghetti code.

OBSERVER

Dynamic NavMesh

When a restored bridge appears, it raises EnvironmentChanged; only the nearby NavMesh is re-baked so guards can follow.

COMPONENT + TYPE OBJECT

TimeAffectable

One component on any object. A ScriptableObject defines its reaction: a rock freezes, a flower grows.

DATA-DRIVEN

Dialogue & Localization

No strings in C#. Dialogue, Thamudic translations and archive text live in data files — new language = new file.

MEMENTO

Archive & Saving

Each collected artifact takes a snapshot of progress, so "Continue Journey" restores exactly what was found.

EVENT QUEUE

Cutscenes & Audio

PauseGameplay is queued before a cutscene (Unity Timeline); the AudioManager is reached through a Service Locator.

// Pattern sketch — Observer + Component // [replace with your real script] public class TimeAffectable : MonoBehaviour { [SerializeField] TimeReaction reaction; // ScriptableObject void OnEnable() => MirrorEvents.OnTimePower += Apply; void OnDisable() => MirrorEvents.OnTimePower -= Apply; void Apply(TimePower power) { reaction.Execute(this, power); // freeze/rewind/FF if (reaction.ChangesPath) WorldEvents.Raise(EnvironmentChanged); // NavMesh re-bakes nearby area } }

AI · Balancing · Game Feel

An AI That Tries to Lose

FIXEDUPDATE

Rubberbanding State Machine

Every physics step the AI compares its Z-distance to the player and switches state.

Panic BrakeToo far ahead → steer into curses
⇄
NeutralClose race → normal dodging
⇄
Catch-UpPlayer lagging → velocity boost
// Pseudocode — replace with your real script void FixedUpdate() { float dz = transform.position.z - player.position.z; if (dz > aheadLimit) state = PanicBrake; else if (dz < -behindLimit) state = CatchUp; else state = Neutral; ApplyState(state); }

Tech Spotlight · Carpet Calamity

Players could win by doing nothing

PROBLEM In testing, players stopped steering and slowed down so the AI finished ahead — last place without effort. CAUSE Player speed could drop freely, and the AI raced normally, so the inverse rule had no counter-pressure. FIX Forced constant forward momentum (no brake) and added a Z-distance state machine in FixedUpdate so the AI also tries to lose. RESULT Tense race to the final second · 2nd place at Qabas Game Jam.
